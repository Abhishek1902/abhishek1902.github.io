The thesis

I've spent seven years making multi-step data systems reliable, observable, and grounded in source-of-truth data — the discipline that decides whether a platform can actually be trusted: evaluation, data quality, lineage, and governance.

That discipline is exactly what most GenAI systems lack. A RAG pipeline is a data pipeline wearing a trenchcoat — chunking is partitioning, embeddings are a transformation step, retrieval is a query optimizer, evals are data-quality checks. The LLM is the new part; making orchestration reliable isn't. That's what I bring — to data platforms first, and to the AI built on top of them.

Plan Craft
Current role · Agentic tooling

An internal web app that optimizes database transformation queries across Hive, SQL Server, DB2 and Snowflake — agentic where judgment helps, deterministic where it matters. Connection profiles capture how queries actually run on each engine; an agentic workflow then gathers statistics and runtime evidence against the input tables, stored procedures and SQL, applies deterministic per-engine rules, and has an LLM generate two candidate rewrites. Both are executed against the live database and compared with the original, so only evidence that the optimization worked is returned. Cut query-tuning time to minutes and improved query performance ~8% for 15–20 engineers across three platform teams.

AI Incident Copilot
Open source · Production RAG

A production RAG system for incident root-cause analysis. Hybrid retrieval (SQL time-filter + pgvector dense search), cross-encoder reranking, and a confidence quality-gate that suppresses low-grounding answers — no context → no LLM call → no hallucination. The part I care most about: a 31-question evaluation harness measuring recall@k and MRR, which surfaced a real multi-hop retrieval gap I diagnosed and scoped fixes for.
